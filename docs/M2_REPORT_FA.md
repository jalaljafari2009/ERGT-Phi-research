# M2 — کالیبراسیون فاز در حالت سایه

## نتیجه

**پیاده‌سازی و آزمایش M2 انجام شد، اما کالیبراسیون معیار پذیرش را پاس نکرد.**
بنابراین `M2_complete=false` و ورود به M3 بر اساس این نتیجه مجاز نیست.
مدل اصلی و پاسخ‌هایش ثابت مانده‌اند. نتیجهٔ ضعیف با تغییر معیارها، افزایش
آموزش پس از مشاهدهٔ نتیجه یا تغییر مخفیانهٔ ورودی anchor به نتیجهٔ موفق تبدیل نشده است.

## چه چیزی ساخته شد؟

آزمون مهندسی شامل **۱۹ تست جدید M2، ۴۴ تست هستهٔ M1 و ۳۰ تست سازگاری M0** بود؛
هر ۹۳ تست موفق شدند. دو تست بازیابی/فاصلهٔ کدها پس از تقویت آزمون RNG دوباره
اجرا و موفق شدند و در شمار کل دوباره شمرده نمی‌شوند. موفقیت این آزمون‌ها، نتیجهٔ
ناموفق کالیبراسیون را تغییر نمی‌دهد.

شبکهٔ فاز دقیقاً از ساختار بخش ۵ سند استفاده می‌کند:

`anchor = pi * tanh(W2 * SiLU(W1 * LayerNorm(Psi0)))`

LayerNorm برای هر توکن مستقل است. ورودی شبکه فقط میدان اولیهٔ بومی است؛
شناسهٔ رابطه، یال صحیح، جواب یا مسیر صحیح به forward اضافه نمی‌شود.
وزن‌های ERGT ثابت‌اند و گرادیانی دریافت نمی‌کنند. شبکهٔ فاز با seed مستقل
روی CPU ساخته می‌شود و RNG مدل پایه را تغییر نمی‌دهد.

کد اولیهٔ هر رابطه `2*pi*r/R` است و در هشت جهان یکسان آغاز می‌شود.
در کالیبراسیون، هر کد حداکثر ۰٫۲۵ رادیان جابه‌جا می‌شود. این محدودیت مانع
یکی‌شدن کدهای سه رابطه می‌شود. پس از پایان آزمایش پارامترهای فعال ثابت می‌شوند.

loss از میانگین سازگاری زاویه‌ای جهان‌ها و Cross Entropy رابطه ساخته می‌شود.
یال‌ها و برچسب‌های صحیح فقط **پس از forward، برای محاسبهٔ loss** استفاده می‌شوند.
انرژی هستهٔ M1 هدف آموزش anchor نیست. در حالت سایه، coupling صفر است،
هندسه اصلاح نمی‌شود و حل‌گر درونی M1 نیازی به اجرای فعال ندارد.

## داده و جلوگیری از نشت اطلاعات

فقط بخش آموزش اجرای پذیرفته‌شدهٔ M0 با بذر دادهٔ 16301 بازسازی شد.
هش آن دقیقاً با گزارش Colab مطابقت داشت:

`e3978bd5688fa0145cc4da581e332d1ee9b67d61aff43fcd8fb0ccec224b6c53`

- ۵۰۴ نمونهٔ اصلی آموزش، شامل ۴۵۴۴ رویداد رابطه.
- ۳۸۲ نمونه و ۳۴۸۰ رویداد برای به‌روزرسانی وزن‌های فاز.
- ۱۲۲ نمونه و ۱۰۶۴ رویداد برای پایش کالیبراسیون.
- تقسیم بر اساس جفت نمونه انجام شد؛ دو عضو یک جفت بین آموزش و پایش جدا نشدند.
- داده‌های tuning، validation، native readiness و افق‌های آزمون اصلی ساخته یا استفاده نشدند.

بخش پایش زیرمجموعه‌ای از دادهٔ **آموزش ERGT** است، نه آزمون مستقلِ تعمیم مدل اصلی.
کار آن انتخاب/رد کالیبراسیون شاخهٔ تازه است. بازسازی داده از توابع مرجع انجام شده
و کد و دادهٔ مرجع ویرایش نشده‌اند.

## پروتکل پیش از آموزش

پروتکل و آستانه‌ها قبل از مشاهدهٔ معیارهای کالیبراسیون در `runs/m2/protocol.json` ثبت شدند.
این آستانه‌های عددی تصمیم‌های جدید پژوهشی‌اند؛ سند ریاضی مقادیر آن‌ها را تعیین نکرده است.

| تنظیم | مقدار |
|---|---:|
| عرض لایهٔ میانی anchor | ۶۴ |
| جهان / رابطه | ۸ / ۳ |
| دمای logits رابطه | ۰٫۲ |
| optimizer | AdamW |
| نرخ یادگیری | ۰٫۰۰۲ |
| batch size | ۱۶ |
| سقف آموزش | ۲۰ دوره |
| تعداد به‌روزرسانی اجراشده | ۴۸۰ |
| حد دقت متوازن پایش | ۷۰٪ |
| حد recall هر رابطه | ۵۰٪ |
| حد کاهش CE نسبت به شروع | ۵٪ |
| حد فاصلهٔ زاویه‌ای کدها | ۱ رادیان |
| حد میانگین تمرکز دایره‌ای فازها | ۰٫۹۸ |
| پنجره‌های موفق متوالی لازم | ۲ |

تمرکز دایره‌ای نزدیک یک یعنی زاویه‌ها تقریباً یکسان‌اند؛ مقدار پایین‌تر به معنی
پراکنده‌بودن آن‌هاست. پراکندگی به‌تنهایی نشان نمی‌دهد کدها رابطه‌ها را درست یاد گرفته‌اند.

## نتیجهٔ واقعی

| معیار | مقدار نهایی |
|---|---:|
| دقت رابطه روی بخش fit | ۴۴٫۴۳٪ |
| دقت متوازن رابطه روی پایش | ۳۳٫۸۶٪ |
| recall سه رابطه روی پایش | ۴۵٫۵۱٪، ۲۶٫۰۹٪، ۳۰٫۰۰٪ |
| CE پایش در شروع | ۲٫۴۹۸۴۲ |
| CE پایش در پایان | ۱٫۲۹۶۶۴ |
| کمترین فاصلهٔ کدهای رابطه | ۱٫۹۶۶۸۸ رادیان |
| بیشترین جابه‌جایی کد از مقدار اولیه | ۰٫۱۰۴۴۸ رادیان |
| تمرکز دایره‌ای فازهای پایش | ۰٫۲۵۴۳۵ |

کاهش loss و معیارهای عدم فروپاشی پاس شدند؛ دقت متوازن و recall هر کلاس پاس نشدند.
دقت متوازن نزدیک حد تصادفی سه کلاس، یعنی ۳۳٫۳۳٪، است. این اجرای تک‌بذر هیچ
ادعای برتری آماری ایجاد نمی‌کند. CE توزیع یکنواخت سه کلاس تقریباً ۱٫۰۹۸۶ است؛
بنابراین پایین‌آمدن CE از شروع نامناسب، به‌تنهایی موفقیت را نشان نمی‌دهد.

## علت ساختاری که مستقیماً بررسی شد

در دادهٔ بومی، گره‌ها ابتدا در فهرست `nodes` می‌آیند و رابطه در بخش `facts` نوشته می‌شود.
`Psi0` در این پیاده‌سازی تابع توکن همان موقعیت، موقعیت آن و هویت همان توکن است؛
هنوز اطلاعات رابطه از توکن facts به توکن گره منتقل نشده است.

شبکهٔ anchor هم طبق سند به‌صورت مستقل روی هر توکن اجرا می‌شود. پس اگر واژهٔ رابطه
را عوض کنیم، ولی توکن‌ها و موقعیت گره‌های مبدأ و مقصد را ثابت نگه داریم، فاز آن دو
گره ثابت می‌ماند. loss رابطه که فقط اختلاف همین دو فاز را می‌بیند، این تغییر را تشخیص نمی‌دهد.

این حالت روی ورودی خام ساخته و **قبل و بعد از آموزش** آزموده شد:
واژهٔ رابطه تغییر کرد، ولی anchor دو سر یال دقیقاً برابر ماند. برای این ورودی
تشخیصی ادعایی دربارهٔ برچسب جواب نهایی نداریم؛ فقط مسیر اطلاعات را می‌سنجیم.

در دادهٔ بازسازی‌شده نیز ۵۵ گروه ویژگیِ دو سر یال یافت شد که عیناً یکسان بودند
ولی چند برچسب رابطه داشتند. این تعارض‌ها ۲۲۴ رویداد را دربرمی‌گیرند.
حد بالای حفظ‌کردن برچسب‌ها بر اساس این گروه‌بندی، ۹۷٫۵۴٪ است؛ **این عدد حد دقت
تعمیم نیست و شکست در آستانهٔ ۷۰٪ را به‌تنهایی اثبات نمی‌کند**. شاهد قوی‌تر برای
کمبود اطلاعات، آزمون تغییر رابطه با ثابت‌ماندن ورودی anchor است.

همچنین هنوز آزمون نشده که پس از افزودن اطلاعات زمینه، یک فاز اسکالر برای همهٔ
ساختارهای رابطه کافی باشد. آن محدودیت جداگانه باید باقی بماند و سنجیده شود.

## حفظ مدل و بازگشت وضعیت

- وزن‌های آموزش‌دیدهٔ ERGT قبل و بعد از کالیبراسیون دقیقاً برابر بودند.
- کل خروجی و تصمیم حل‌گر سخت روی نمونهٔ بررسی‌شده دقیقاً برابر ماندند.
- checkpoint کامل شاخهٔ آموزش‌دیدهٔ ناموفق در `rejected_full_state.pt` نگهداری شد.
- حالت عملیاتی به وضعیت اولیهٔ شاخه، optimizer، RNG و پیشرفت داده بازگردانده و سپس ثابت شد.
- مدل کالیبره‌شدهٔ پذیرفته‌شده تولید نشد؛ اثرگذاری بر هندسه فعال نشده است.

قالب ذخیرهٔ کامل پژوهشی در مرز گام optimizer استفاده می‌شود. آزمون مستقل ادامهٔ
آموزش شاخهٔ M2 در فرایند تازه، برابری با اجرای پیوسته را بررسی می‌کند.
خطای عددی در گام آموزش نیز باعث بازگشت کامل همان گام می‌شود.

## اجرای مجدد و فایل‌ها

از ترمینال پروژه:

```powershell
python -B scripts/run_m2.py
```

این دستور آزمایش ثبت‌شده را دوباره اجرا می‌کند و خروجی‌های `runs/m2` را بازنویسی می‌کند.
پایان موفق اسکریپت، به معنی پذیرش علمی کالیبراسیون نیست؛ مقدار `status` را بخوانید.

آزمون مهندسی مستقل:

```powershell
python -B -m pytest -q tests/test_shadow_phase.py
```

کدها: `ergt_phi/shadow_phase.py`، `shadow_data.py` و `shadow_metrics.py`.
نتیجه: `manifests/m2_status.json`؛ منحنی‌ها: `runs/m2/curves.json`.
وزن‌ها و وضعیت‌های کامل در `runs/m2` هستند و وارد کنترل نسخه نمی‌شوند.
