# اعتبارسنجی قفل سند و برنامهٔ دو‌مسیره

تاریخ: ۲۰ سپتامبر ۲۰۲۶. تصمیم: [ADR-0004](../decisions/ADR-0004.md).
دامنه: حفاظت سند، اصلاح برنامه و ابزارهای مرتبط؛ هیچ آموزش، اجرای Colab یا پذیرش فاز علمی تازه انجام نشد.

## محتوای محفوظ و مجوزهای محلی

- `docs/MATHEMATICAL_SPEC.md`: ۲۳۴۵۰ بایت؛ SHA-256
  `04ac57cc76395f7b032356bcac38b70b796233ac4aa59ba26a6b2474977c5d90`.
- مقایسه با blob همین فایل در HEAD پیشین `6e89c1e76e8943f51f5cc5138dde5b47a3889253`:
  بایت‌به‌بایت برابر. متن سند، مرجع و آرشیو قدیمی تغییر نکردند.
- ReadOnly و ACL منع Write/Delete فایل اعمال شد. آزمایش نخست نشان داد Windows می‌تواند
  حق Delete را از والد بگیرد؛ قاعدهٔ غیرموروثی منع DeleteChild روی `docs` این مسیر را بست.
- با `CreateFileW` و `OPEN_EXISTING`، بدون نوشتن یا حذف، دسترسی‌های write، append، تغییر
  attributes و delete برای spec رد شدند. همان بررسی برای write/delete فایل برنامه موفق بود؛
  بنابراین امکان ویرایش معمول برنامه حفظ شد. [گزارش ماشینی](spec_lock_access_20260920.json).
- `check_spec_lock.py --require-read-only` موفق است؛ این ابزار hash و ویژگی فقط‌خواندنی را
  بررسی می‌کند، نه ACL. بررسی ACL با گزارش مستقل بالا انجام شده است.
- Git فقط محتوا/manifest و دستور بازاعمال را حفظ می‌کند. قفل سیستم‌عامل محلی است و
  مالک/مدیر سیستم می‌تواند عمداً آن را باز کند. این محدودیت در manifest و ADR ثبت شده است.

## بررسی کد و آزمون‌ها

۱. اجرای زیر **۳۵ تست موفق در ۶٫۱۲ ثانیه** داشت:

```powershell
python -B -m pytest tests/test_spec_lock.py tests/test_research_workflow.py -q -p no:cacheprovider --basetemp .cache/pytest-spec-lock-ordinary-20260920
```

موارد جدید شامل تغییر هم‌اندازهٔ محتوا، تغییر پایان‌خط، فقدان سند، تغییر مسیر manifest و
توقف CLI پیش از ورود به workflow است. بازبینی مستقل ایراد `--root` را پیدا کرد؛ guard
اکنون checkout مقصد را بررسی می‌کند و تست ریشهٔ مقصدِ خراب نیز پاس شده است.

۲. بررسی بسته و نوت‌بوک **۸ تست موفق در ۵٫۸۱ ثانیه** داشت:

```powershell
python -B -m pytest tests/test_colab_workflow.py -q -p no:cacheprovider --basetemp .cache/pytest-spec-package-final-20260920
```

وجود spec و manifest آن در بسته‌های تازه، اعتبارسنجی inventory، بسته‌های نتیجه و شکست
اجرا بررسی شدند. نوت‌بوک هماهنگ‌کنندهٔ دو protocol ساخته نشده؛ فقط نمایش metadata مسیرها
به مولد فعلی اضافه شده است. بسته‌های قفل‌شدهٔ تاریخی بازتولید یا بازنویسی نشدند.

در مجموع **۴۳ تست موفق**؛ این‌ها تست زیرساخت‌اند و شاهد عملکرد علمی ERGT-Phi نیستند.
Pythonهای تغییرکرده و JSONهای تازه نیز از نظر نحو بررسی شدند.

## برنامه، تاریخچه و منابع

- گام‌های ۱ تا ۸ مسیر A در برنامه با متن HEAD قبلی مقایسه شدند و پس از یکسان‌سازی
  پایان‌خط‌ها برابر بودند؛ آستانه‌ها، قیود و وابستگی‌های آن‌ها حفظ شده‌اند.
- جدول سؤال‌های A/B، نتایج مستقل، کنترل‌ها، سقف هزینه و ماتریس تصمیم به برنامه اضافه شده است.
- محدودیت یک verdict برای هر run و نیاز فعلی به experimentهای همتا صریح است؛ قابلیت
  orchestration دو اجرا به‌عنوان کار آینده معرفی شده است.
- نسخهٔ ۱ هدف در goals حفظ و نسخهٔ ۲ با راهبرد دو‌مسیره فعال شد. A همچنان در M2 با
  تحویل ناقص است و B planned/not_executed؛ registry علمی همچنان فقط WF-E001 را دارد.
- R3 با هش اصلی `72ba826900cd4a6f7ac64de076a969d2a932cefbac3f108410a17ab92dc08d9c`
  بایت‌به‌بایت بایگانی شد. متن مجوز پژوهشگر و معنای تصمیم کنار آن ثبت و hashها بررسی شدند.
- AGENTS، STATE، ARCHITECTURE، WORKFLOW، INDEX و دفتر تصمیم‌ها به برنامه و قفل وصل شده‌اند.

## بازیابی پس از قطع ارتباط

فایل‌های ساخته‌شده، اندازه‌ها، hash منابع، تاریخچهٔ هدف و وضعیت Git مجدداً بررسی شدند؛
فایل تغییرکردهٔ ناقص یا منبع ازدست‌رفته در این ممیزی مشاهده نشد. خروجی یک نشست تست
بسته/نوت‌بوک پس از قطع ارتباط قابل بازیابی نبود؛ آن اجرا مبنای نتیجه قرار نگرفت و
تست‌ها با basetemp تازه دوباره اجرا شدند. نتیجهٔ ۸ تست بالا خروجی بازیابی‌شدهٔ اجرای تازه است.

تلاش ابتدایی pytest در sandbox به خطای دسترسیِ پوشهٔ موقت Windows رسید و Set-Acl نیز
دسترسی کافی نداشت. اجرای همان کارهای محدود با دسترسی عادی کاربر موفق شد؛ آزمون حذف
یا نادیده گرفته نشد. پوشه‌های موقت خارج از Git هستند و جزو شواهد علمی یا commit نیستند.

قدم بعدیِ علمی طبق STATE، آماده‌سازی آزمایش‌های A/B و تحویل M2 است؛ این گزارش ادعای
ساخت یا اجرای آن نوت‌بوک‌های علمی را ندارد.
