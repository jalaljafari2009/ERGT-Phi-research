# ADR-0001 — زیرساخت آزمایش‌های نسخه‌دار و زنجیرهٔ شواهد

- تاریخ ثبت: ۲۰۲۶-۰۹-۲۰
- وضعیت: پذیرفته برای زیرساخت؛ مجوز فعال‌سازی علمی M3 نیست.
- درخواست مبنا: پژوهشگر خواسته است ایجنت برنامه، کد، نوت‌بوک، نتایج، مرور و commit هر پیشرفت را پیگیری کند.
- والد: برنامهٔ `docs/OPERATIONAL_ROADMAP_FA.md`؛ commit مبنا `e9c564aa247c0b05c126b40bdc106f0f335f4e17`.

## مسئله

شواهد توسعه در چند manifest و پوشهٔ runs پخش شده‌اند. نوت‌بوک، نسخهٔ کد، checkpoint و
نتیجهٔ هر تلاش پیوند یکتای اجرایی ندارند. قبولی عددی M2-Q با آمادگی تحویل مدل اشتباه شد؛
runner آن وزن منتخب ذخیره نکرده است. طرح اصلی و تغییر anchor نیز باید جدا قابل ردیابی باشند.

## تصمیم

شناسهٔ آزمایش، revision و run مستقل ثبت شوند. پروتکل و نوت‌بوک قبل از اجرا نسخه بخورند؛
بستهٔ سورس قفل هش داشته باشد؛ نتیجهٔ Colab فقط پس از تطبیق هویت، فایل‌ها و هش‌ها وارد شود.
جمع‌بندی ماشینی معیارها از داوری پژوهشی جدا باشد. تصمیم pass/revise/inconclusive به ADR
و شواهد همان اجرا وصل شود؛ هیچ returncode صفر یا تست زیرساختی یک فاز علمی را پاس نمی‌کند.

هر نسخه در `research/experiments/<experiment_id>/<revision>/` و هر اجرای آن در `runs/<run_id>/`
همان نسخه نگهداری می‌شود. فایل‌های بزرگ در `research/artifacts/` خارج از Git نگهداری شده و
فهرست اندازه، هش و محل بازیابی آن‌ها ثبت می‌شود. بستهٔ upload در `research/packages/` است.
`AGENTS.md` مسیرها و وظایف را برای هر جلسه به ایجنت می‌دهد.

## گزینه‌ها و علت انتخاب

- ویرایش مداوم یک نوت‌بوک: کنار گذاشته شد؛ نسبت نتیجه با کد قبلی مبهم می‌شود.
- commit تمام checkpointها و ZIPها: کنار گذاشته شد؛ Git برای این حجم مناسب نیست.
- revision ثابت با artifact inventory و محل Drive: انتخاب شد؛ ردگیری و بازیابی را حفظ می‌کند.
- اجرای خودکار و دائمی Colab بدون اتصال: ادعا نمی‌شود؛ notebook اجرای دستی پژوهشگر را
  هدایت می‌کند و ایجنت در جلسهٔ بعد وضعیت و inbox را پیگیری می‌کند.

## اثر بر معماری و هدف

این تصمیم فقط چرخهٔ پژوهش را تغییر می‌دهد. فرمول انرژی، آستانه‌های M2 و قراردادهای native
تغییر نمی‌کنند. هدف M2 بعدی ساخت checkpoint منجمد و تأیید اتصال است. تغییرات هدف یا مدل
باید ADR بعدی با دلیل، گزینه‌های ردشده، آزمایش مرتبط و اثر بر مقاله داشته باشند.

## اعتبارسنجی

آزمون‌های import امن، عدم پذیرش هش/نسخهٔ اشتباه، ساخت notebook، صادرات شکست و زنجیرهٔ
آزمایش زیرساختی `WF-E001/v001` اجرا می‌شوند. نتیجهٔ آن فقط صحت workflow را می‌سنجد.
نتیجهٔ اجرای واقعی به‌صورت run ثبت می‌شود؛ این ADR نتیجه‌ای را پیشاپیش ادعا نمی‌کند.

## پیگیری

تکمیل runner M2، ذخیره و freeze منتخب، تأیید دادهٔ تازه، آداپتر واقعی phi/preview و
