# ADR-0013 — بازنگری M2-E005/v001 به‌دلیل ناسازگاری تعریف cohort با قفل توسعه

- تاریخ: ۲۲ سپتامبر ۲۰۲۶.
- وضعیت: **accepted برای اصلاح مهندسی نسخه؛ بدون نتیجهٔ علمی**.
- مبنای مجوز: ادامهٔ صریح پژوهشگر و الزام workflow به حفظ اجرای ناموفق.
- والد: [ADR-0012](ADR-0012.md).
- شاهد: `M2-E005/v001/20260922T103000Z-m2e005-v001-local`.

## مسئله و شاهد

پیش‌اجرای package-bound پیش از محاسبهٔ target متوقف شد. قرارداد v001 برای ساخت cohort تازه،
hopهای `2,3,4,6,8,12,16` با شمار ۳۲ pair را ثبت کرده بود؛ این تعریف هم با lock پذیرفته‌شدهٔ
`M2-E003/v004` ناسازگار بود و هم چون ۳۲ بر هفت سناریوی مولد بخش‌پذیر نیست، تابع
`_balanced_training_cohort` آن را رد کرد. runner با return code غیرصفر خاتمه یافت و هیچ
challenge row، feature cache، readout یا metric علمی تولید نشد.

این failure پیش از مشاهدهٔ target تازه رخ داد؛ بنابراین اصلاح تعریف cohort، tuning پس از دیدن
نتیجه نیست. checkpointها و سند ریاضی تغییر نکرده‌اند و M3/M8 بسته‌اند.

## گزینه‌ها و تصمیم

۱. تغییر v001 درجا رد می‌شود، چون protocol و package آن release شده‌اند. ۲. ساخت cohort تازه با
شمار بخش‌پذیر نیز رد می‌شود، چون هویت cohort را نسبت به قفل E004 عوض می‌کند. ۳. نسخهٔ v002 فقط
تعریف دقیق پذیرفته‌شده را برمی‌گرداند: hopهای `1..8`، برای هر hop تعداد ۲۸ pair، و ۲۸ pair
unsupported؛ seedها، پنجره‌ها، interventionها، target، بودجهٔ readout، gateها و تفسیر ثابت
می‌مانند. گزینهٔ سوم انتخاب شد.

## دامنه و اقدام بعد

این تصمیم هیچ شاهدی دربارهٔ Phase یا مناسب‌بودن پنل ایجاد نمی‌کند. v002 باید lock cohort را پیش
از اجرای native بازتولید و hash آن را کنترل کند، سپس package و run تازه بسازد. اگر هر gate علمی
پس از اجرای v002 رد شود، نتیجه بدون تغییر threshold با تصمیم جداگانه `revise` می‌شود. M3 و M8
همچنان بسته می‌مانند.
