# پرونده‌های تاریخی پژوهش

این پوشه گزارش، manifest، نوت‌بوک موجود، خروجی کوچک و منشأ کد هر گام را کنار هم
نگه می‌دارد. [INDEX](../INDEX.md) فهرست هر ده پرونده و ترتیب مسیر را نشان می‌دهد.

```text
LEGACY-<id>/
  README.md                پرسش، نتیجه، محدودیت، تصمیم بعدی و لینک مدارک
  reports/                 گزارش‌های اصلی با بایت‌های محفوظ
  manifests/               نتیجه و پروتکل‌های موجود
  notebooks/               نوت‌بوک تاریخی، اگر واقعاً موجود بوده
  evidence/<run_dir>/      خروجی‌های کوچک و نمودارها برای Git
  git_evidence/            نسخه‌های بازنویسی‌شده که از Git بازیابی شدند
  inventory.json           مسیر قدیمی، مسیر فعلی، hash و اندازه
  source_provenance.json   کد متناظر با hashهای ثبت‌شده در تاریخچهٔ Git
```

فایل کامل هر اجرای موجود در `research/artifacts/legacy/<id>/<run_dir>/` حفظ شده است.
شواهد کوچک آن به‌صورت بایت‌به‌بایت در evidence نگهداری می‌شوند تا با clone ریپو هم
گزارش قابل بررسی باشد. وزن‌ها و ZIPها به Git وارد نمی‌شوند؛ دو ZIP اصلی M0 در
`research/artifacts/source_archives/` و مشخصاتشان در [منابع](../sources/register.json) هستند.

این پرونده‌ها از پیش پروتکل جدید نداشتند. برایشان run یا نوت‌بوک ساختگی ایجاد نشده است؛
فقط M0 نوت‌بوک تاریخی دارد. بازاجرای تازه با ابزار علمی فعلی به پروتکل و نسخهٔ تازه
در `research/experiments/` نیاز دارد. اصل گزارش‌ها ممکن است برداشت‌های قدیمی داشته
باشد؛ README هر پرونده و [STATE](../STATE.md) حدود معتبر نتیجه را توضیح می‌دهند.

`source_provenance.json` کد هر شاهد را با Git تطبیق می‌دهد. commit تطبیق‌یافته محل
بازیابی بایت‌هاست و لزوماً commit زمان اجرای آزمایش نیست. منبعی که فقط توصیف طراحی
دارد، با همین عنوان ثبت می‌شود. [نقشهٔ مسیرهای قبلی](path_map.json) آدرس‌های داخل
متن‌ها و manifestهای قدیمی را به محل فعلی متصل می‌کند.

بازیابی‌های مهم: M0 پیش از GPU، نخستین اجرای M1 و manifest/protocol اجرای M2 اولیه.
فایل خام بازنویسی‌شدهٔ M2 اولیه که در Git نبود، بازیابی‌شده فرض نشده است.
