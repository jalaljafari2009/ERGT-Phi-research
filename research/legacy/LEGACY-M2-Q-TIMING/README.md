# LEGACY-M2-Q-TIMING — قرارداد جداگانهٔ Q تأخیری

این پرونده یک گام طراحی/پیاده‌سازی را نگه می‌دارد و run مستقل Colab نیست. در commit `40b6ad4c90850b5e268983cb8b0e14dbafe4dbe3` تبدیل proposal بومی به Q و نگهداری detached نسخهٔ قبلی آن پیاده‌سازی شد.

## فایل‌ها

- [گزارش تاریخی](reports/M2_LAGGED_Q_FA.md).
- کد [lagged_q.py](../../../ergt_phi/lagged_q.py) و آزمون [test_lagged_q.py](../../../tests/test_lagged_q.py).
- منشأ تصمیم: [probe بومی](../LEGACY-M2-PROPOSAL/README.md)؛ ادامهٔ آزمایشی: [Q-shadow](../LEGACY-M2-Q-SHADOW/README.md).

`native_proposal_q` توزیع مبدأ، مقصد و رابطه را ترکیب می‌کند؛ کلاس null در جرم غیر-null حساب می‌شود و نباید حضور رابطه دوباره اعمال شود. `LaggedQ` مقدار detached قبلی را با clone بازمی‌گرداند و دادهٔ دارای gradient یا غیرمتناهی را رد می‌کند.

## مرز اعتبار

گزارش قدیمی از enforce شدن زمان‌بندی سخن می‌گوید. ممیزی بعدی نشان داد کلاس فقط آرایهٔ `[E,R]` را نگه می‌دارد؛ هویت یال، sample/world، patch، step و ترتیب consume/commit داخل حلقهٔ native هنوز قرارداد کاملی ندارند. آزمون مستقل این ظرف حافظه، اجرای یک گام تأخیر واقعی در مدل یکپارچه را ثابت نمی‌کند.

برای این گام، manifest اجرای مستقل، خروجی آموزش، checkpoint یا نوت‌بوک ثبت نشده است. وجود آن‌ها در این پرونده ادعا نمی‌شود. تکمیل metadata و آزمون اتصال در [بازبینی جاری M2](../../phase_reviews/M2_CURRENT.md) باز است.
